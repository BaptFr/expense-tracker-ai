JUDGMENT CALL — "DESCRIPTION AS VENDOR"
-----------------------------------------
The Expense type (src/types/expense.ts) has no vendor/merchant field:
{ id, date, amount, category, description, createdAt }. Per the task's
explicit instruction, I did NOT modify the shared data model (that would
risk breaking other parallel branches relying on the current shape).
Instead, each expense's free-text `description` field is treated as the
vendor/merchant name for grouping purposes. Grouping normalizes by
trim().toLowerCase() so e.g. "netflix" and "Netflix" merge into one
vendor entry, but the displayed name preserves the original (trimmed,
non-lowercased) casing from the first expense encountered in that group.
Empty/blank descriptions are skipped (excluded from vendor rankings)
since they can't represent a meaningful vendor name.

This is an interpretation driven entirely by the current schema, not a
hidden assumption — flagging it explicitly here as requested. If a
dedicated "vendor" field is added to the shared Expense type in a future
migration, this page's grouping key should switch to that field instead
of description.
